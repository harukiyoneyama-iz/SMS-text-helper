# 出力フォーマット規則: コマンドの提示

## 適用対象

非エンジニア・初心者ユーザー（特にバイブコーディング展開を行う AI 事業部・営業・管理部門のメンバー）。
エンジニア相手では簡略化可。

## 必須フォーマット

コマンドを提示する際は、以下 4 点を必ず含める。

### 1. ターミナル種別と起動方法を冒頭で明示

ユーザーが「どこを開いてどう入力するか」を一意に理解できる導入文を必ず付ける。

OK 例:
> **Windows PowerShell を開いてください**（スタートメニュー → 「powershell」と入力 → Enter）。
> 以下を実行:

> **Mac の Terminal を開いてください**（Spotlight 検索 ⌘+Space → 「terminal」と入力）。
> 以下を実行:

OS 不明の場合は Windows と Mac の両方を併記。

NG 例:
- いきなり ```` ```bash ```` ブロックを置く（Windows ユーザーが詰まる）
- 「ターミナルで以下を実行」とだけ書く（どのターミナル？）

### 2. コマンドブロックは独立させる（1 ブロック 1 コマンド原則）

複数コマンドを `;` や `&&` で連結しない。コピペ単位を最小化し、エラー時にどこで詰まったか切り分けられるようにする。

NG:
```powershell
cd C:\CursorPJ\guideline; git status; git diff
```

OK:
```powershell
cd C:\CursorPJ\guideline
```

```powershell
git status
```

```powershell
git diff
```

例外: 不可分な前後関係があり、まとめないと意味が崩れる場合のみ連結可。その場合も「これは一塊で実行する」と明記。

### 3. 期待結果と失敗時の対処を併記

コマンド実行後に何が表示されれば成功か、失敗時のよくある原因と次のアクションを記す。

例:
> **期待結果**: プロンプトが `PS C:\CursorPJ\guideline>` に変わる
> **失敗時**: 「パスが見つかりません」エラー → エクスプローラーで該当フォルダが存在するか確認

### 4. ステップ番号を付ける

複数手順がある場合は「Step 1」「Step 2」と番号付け。読み手が中断・再開できるように。

## フォーマット例（推奨パターン）

---

**Step 1: リポジトリのフォルダに移動**

Windows PowerShell を開いてください（スタートメニュー → 「powershell」と入力 → Enter）。
以下を実行:

```powershell
cd C:\CursorPJ\guideline
```

**期待結果**: プロンプトが `PS C:\CursorPJ\guideline>` に変わる

**失敗時**: 「パスが見つかりません」 → エクスプローラーで `C:\CursorPJ\guideline` が存在するか確認

---

**Step 2: 状態確認**

引き続き同じ PowerShell で以下を実行:

```powershell
git status
```

**期待結果**: 変更されたファイルの一覧が表示される

**失敗時**: 「fatal: not a git repository」 → Step 1 のパスが間違っている可能性

---

## NG パターン早見表

| パターン | 何が悪いか |
|---|---|
| ターミナル種別未明示 | Windows ユーザーが Bash 構文で詰まる |
| 複数コマンド連結（`;` `&&`） | エラー時にどこで失敗したか切り分け不能 |
| 期待結果なし | 成功したかユーザーが不安、自走できない |
| 一気に 10 コマンド | 途中で止まれず、エラーで全部やり直し |
| `cd` の絶対パス省略 | 直前のディレクトリ次第で動かない |

## 補足: ターミナル起動方法のテンプレ文

そのまま貼って使える表現集:

- **Windows PowerShell**: 「Windows のスタートメニューで『powershell』と入力 → Enter で起動」
- **Mac Terminal**: 「Spotlight 検索（⌘+Space）で『terminal』と入力 → Enter で起動」
- **Linux**: 「Ctrl+Alt+T でターミナル起動（ディストリビューションにより異なる）」
- **既に開いているターミナルで続ける**: 「先ほどの PowerShell の続きで以下を実行」

## エンジニア向けの簡略化条件

以下が満たされる相手にはフォーマットを簡略化可（連結コマンド・期待結果省略 OK）:
- システム開発部のエンジニア
- ターミナル操作に慣れていることを本人が明言した場合
- 既存の作業フローを高速で進める必要があるとき

それ以外（特にバイブコーディング展開対象の 20 名）では本ルールを厳守。
