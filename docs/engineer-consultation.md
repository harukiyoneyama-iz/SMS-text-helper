## 外部送信先

**なし**。Phase 1 は Dev Container 内でローカル起動するのみで、BigQuery からの読み取り接続しか持たない。ディレクターへの依頼文は画面からコピーして人が Slack に貼る運用とし、アプリからの送信は実装しない。

## 必要権限

- `gnote-analytics.gnote_sms_catalog`（asia-northeast1）の**ビュー5本に対する閲覧権限のみ**
- クエリ（ジョブ）実行権限
- 生テーブル（`gnote_jty_prod`）へのアクセス権は**持たない**。テーブル作成権限・書き込み権限も無し
- 認証はサービスアカウントキーを使わず、`gcloud auth login`（本人アカウント）のみで完結する
  - **2026-09-25 内田さん回答により更新**: 当初想定していたなりすまし用サービスアカウント（impersonation）は不要になった。米山さん本人の Google アカウントに直接、上記ビュー5本への閲覧権限とクエリ実行権限が付与されている。有効期限（下記）はこの変更で延長しない

## 想定事故

1. **クライアント同席中の画面に、他クライアントの文面・店舗名・電話番号が表示される** → 商談上の信用失墜。伏せモード（サーバ側でマスクしてから画面に渡す）で防ぐ
2. **ビューの伏せ処理から漏れたお客様の氏名が画面に出る** → 個人情報の漏洩。現時点は伏せ漏れ0件だが、ビューが更新されると再発しうる
3. **ローカルキャッシュ（SQL結果の保存ファイル）を持ち出す・コミットする** → 文面データの流出。`.gitignore` で除外し、Dev Container 内に閉じる
4. **ビューに列が追加され、想定していない個人情報が混入する** → 内田さんに追記を依頼する際は、追加される列の中身を確認してから使う

## 許可範囲

1. BigQuery は上記ビュー5本の**読み取りのみ**。生テーブルへの権限要求・書き込み・テーブル作成は行わない
2. Phase 1 は **Dev Container 内のローカル起動のみ**。Cloud Run へのデプロイ・社外公開はしない
3. 一括CSVエクスポート機能は付けない（画面からのコピーのみ）
4. **AI分類（本文を外部APIへ送る処理）は行わない**。導入する場合は再トリアージ・再相談
5. ローカルキャッシュは Dev Container 内に閉じ、git 管理対象にしない
6. 上記を超える変更（Phase 1.5 の全員配布、外部送信先の追加、書込権限の追加、kintone 等との接続）は**再相談・再承認**

## 期限切れ / 変更時のルール

- 有効期限を過ぎたら CI が fail → 再相談・再承認必須
- 「許可範囲」を超える変更は再相談必須（PR 説明欄に記載）
- 例外を許す場合も**必ず期限を切る**（無期限例外は禁止）
